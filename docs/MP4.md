# MP4 无损转封装

本文说明 Course Fetch 如何在下载过程中把 HLS 的 MPEG-TS 转成 MP4。使用方法见 [README](../README.md)，整体架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 录像编码

课堂录像的 TS 中是以下两路流，都能原样放入 MP4：

- **视频**：H.264 High@4.0，1920×1080，25 fps，含 B 帧
- **音频**：AAC-LC，48 kHz 立体声，ADTS 封装

因此脚本只做转封装（remux），不重新编码，画质和音质与原始 TS 完全一致。

## 方案选择

| 方案 | 结论 |
| --- | --- |
| 下载中流式 TS → MP4（采用） | 自己实现精简的 TS 解复用和普通 MP4 封装，边下载边写 `mdat`，结束时写 `moov`。不需要额外依赖，内存有界 |
| ffmpeg.wasm | 体积约 30 MB，受页面 CSP 和 COOP/COEP 限制；MEMFS 需要把输入和输出都放在内存里，违反有界内存要求 |
| 下载完成后再 remux | 要先写 `.ts` 再读回，磁盘 I/O 和临时空间翻倍；内存分支没有可回读的文件 |
| mux.js / mp4box.js | 面向 MSE 和 fMP4，自带缓冲。这里只需支持 H.264 + AAC，引入它们弊大于利 |
| WebCodecs | 只能用来重新编码，不符合要求 |

## 流程

1. `downloadHls` 每解密一个分片，就交给 `remux.js`。
2. `ts-demux.js` 增量解析 188 字节 TS 包、PAT/PMT 和 PES。跨分片的半个包和未结束的 PES 会被缓存。
3. `codecs.js` 读取 SPS（分辨率、profile）和 ADTS 头（采样率、声道）。
4. 视频：从 Annex B 起始码改为 4 字节长度前缀，并去掉 AUD。音频：去掉 ADTS 头。
5. 每个分片的视频样本和音频样本各写成一个 chunk，直接写入 `mdat`。
6. 下载结束后写入 `moov`，其中包含样本表、`avcC`（SPS/PPS）和 `esds`（AudioSpecificConfig）。最后按位置回填文件开头的 64 位 `mdat` 大小。

```
ftyp | mdat(64 位大小，最后回填) | 样本数据…… | moov
```

## 时间戳

- 视频保留原始 DTS 和 CTS；B 帧的显示偏移写入 `ctts`。
- 音频每帧固定 1024 个采样，时间轴按采样数累计，不受 TS 中 90 kHz 时间戳取整抖动的影响。
- 音视频首帧的起始差（约 17 ms）用 `elst` 空白编辑保持同步。
- 处理 33 位 PTS 回绕。
- 时间戳断点（回退或跳变超过 10 秒）按上一帧时长接续，并在完成信息中提示。
- 源中真实缺失的音频（0.1–10 秒）保留为空白，以维持音画同步。

## 内存与性能

- 视频数据不会整段留在内存中。额外只保留跨分片的半帧和样本表（每个样本约 4 字节）。2 小时录像约 50 万个样本，样本表约数 MB，与文件大小无关。
- 单次写入不超过一个分片。
- 只做字节解析和拷贝：在 Node 中转换 730 MB、2 小时的录像约需 1–2 秒，远快于下载速度。
- MP4 比 TS 小约 5–10%，因为去掉了 TS 和 PES 包头。
- 超过 4 GB 时 chunk 偏移自动改用 `co64`。

## 文件结构与兼容性

- 生成的是普通（非分片）MP4，`moov` 在文件末尾。本地播放器和浏览器都能直接播放和拖动进度。
- 如需上传网页做流式播放，可以用 `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4` 把 `moov` 移到开头。
- 目录 / OPFS 临时文件写入用 `FileSystemWritableFileStream` 的按位置写入回填文件头。内存分支（无 OPFS 的 Safari / Firefox、跨域 iframe）在完成前替换内存中的文件头块。

## 无法无损封装时

以下情况会在写出任何 MP4 字节之前就被识别：

- PMT 中出现 H.264 和 ADTS AAC 以外的音视频流，例如 H.265/HEVC、MP3、AC-3、AAC-LATM；
- 有多条视频或多条音频流。

这时脚本会删除 `.mp4`，在同一目录改存为 `.ts`。已下载的分片原样写入，不重新请求，界面会写明原因。

其它情况：

- 已经写出数据后才出现的变化（中途改变 SPS/分辨率、音频参数或 PMT）无法回退，该条失败，并提示改用 TS 格式。
- 解密后的数据不是 TS（key 或 IV 错误）时直接失败，不会回退保存无效数据。
- 任何情况下都不会静默重新编码。

## 验证结果

用 3 条真实录像（各约 2 小时、730 MB–1 GB）与 `ffmpeg -c copy` 的结果对比：

- 帧数一致，视频 PTS/DTS 完全一致；
- 解码后的视频帧逐帧相同；
- 音频数据逐字节相同。

## 离线转换

`tools/ts2mp4.mjs` 使用同一个模块，按块读取并直接写盘：

```bash
npm run ts2mp4 -- "L01-2026-09-07-第7-8节.ts"     # 输出同名 .mp4
npm run ts2mp4 -- in.ts out.mp4 --chunk=65536    # 指定读取块大小
```
